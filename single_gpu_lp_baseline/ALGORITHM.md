# 当前算法：结构场引导的容量约束标签传播

这是对现有实现的定义，不是已验证的论文创新声明。主实现为
`src/main.cu`、`src/partitioner.cu`、`src/graph.cpp`，配置定义在
`include/partitioner.hpp`。主程序不调用 Python、METIS、Jet 或 CPU 最小割。
原图始终不收缩，没有粗图、匹配或反粗化。

## 目标与输入

输入为无权、双向对称 CSR。磁盘 offsets/indices 为 int64，内部邻居编号
转为 int32；输出为每点一个 int32 分区标签。输入必须符合加载器的编号范围。
加载器保留重复邻接条目；因此允许输入表示平行边，但仍要求反向条目保持对称。
配对算子的 `adjacency(u,v)` 使用 u 行中 v 的条目重数，而不是布尔相邻标志。

设标签为 L(v)，负载为 N_p，最小化无向切边：

`C(L) = 1/2 * sum_v sum_{u in N(v)} [L(u) != L(v)]`。

最终约束为 `N_p <= floor(alpha * n/k)`，默认 alpha=1.10；
不设置最小点数。代码使用 float 保存 alpha，极靠近整数边界时需按实际容量校验。
切边比例是无向切边/无向总边，也等于双向跨区邻接条目/全部邻接条目，
不能混用单向分子和双向分母。

## 一次完整运行

```text
原图 CSR
  → 距离分离种子 + 容量约束距离增长
  → 重复：结构场扩散/投影 → 负载调整 → 切边增益标签传播
  → （可选）最终可行阶段：有界双向配对交换 → 有界连通块标签传播 → 重新切边下降
  → 恢复最好可行标签 → 冲突消解的增益传播 → 输出
```

1. **初始化。** 在局部高度数候选中选择距离分离种子，计算图距离，
   按距离偏好和容量配额分配顶点，未分配点有兜底处理。
   初始化容量接近平均值 `ceil(n/k)`，这不是最终最小负载约束。
   默认固定搜索种子；外部初始划分是可选研究入口，不是默认流程。
2. **结构场。** `ENABLE_FIELD=1` 时从当前标签构造中心化信号
   `H[v,p] = [L(v)=p] - 1/k`，重复
   `H <- 0.5 H + 0.5 D^(-1/2) A D^(-1/2) H`。
   默认扩散 8 轮。每个点优先选择场值最大的标签，但新标签必须出现在邻居中；
   用最大与次大场值之差作为配额竞争优先级。这不是实际切边增益。
   `ENABLE_FIELD=0` 时跳过初始场构建、全部扩散和所有 field projection；
   `FIELD_ROUNDS=0` 不等价于关闭该阶段。
3. **容量控制。** 迁移候选按目标分区汇总，受目标剩余容量限制。
   搜索前两轮允许较松容量：默认 1.20、1.15，随后收紧到 1.10。
   中间允许不可行探索，但最终仅保留满足 1.10 的解。
   balance 使用邻接和负载压力启发式，可能增加切边；它不等价于只修复超载点。
4. **增益传播。** 统计 `c(v,p)=|N(v) ∩ V_p|`，单点从 a 到 b 的收益为
   `g(v,a→b)=c(v,b)-c(v,a)`。正常下降阶段要求正收益，超载修复另行处理。
   默认每个全局周期最多 5 轮 balance、50 轮 descent，共 5 个周期。
   同步批次中的相邻迁移会相互影响，不能把单点收益简单相加当作批次真实收益。
5. **可选双向配对交换。** `PAIR_EXCHANGE=1` 且当前状态满足最终
   `1.10` 最大容量时启用；不可行探索阶段不启用。每个顶点从邻居标签中按
   `g` 选至多两个目标，按有向分区对分桶，每桶按收益降序、顶点编号升序保留
   至多 32 个候选。对 `(A,B)` 和 `(B,A)` 做有界交叉枚举，每个无序分区对只保留
   一个严格正收益交换。交换收益是
   `G(u,v)=g(u,A→B)+g(v,B→A)-2*adjacency(u,v)`；其中 adjacency 是
   CSR 重数，不能把两个单点收益直接相加。随后在 GPU 上按收益和端点编号的稳定
   优先级贪心选择子集：接受交换不能共享端点，且不同交换的四个跨端点之间不能有边。
   同一交换的两个端点可以相邻。候选全部来自同一标签快照，筛选后统一提交；两区
   单位点权重负载不变，提交后完整重建邻居计数并完整重算切边。每个全局周期最多两
   轮；每轮有交换才追加受现有 `refine_rounds` 限制的 descent。设备端原始候选容量
   固定为 `n * PAIR_TOP_TARGETS`（第一版最多 `2n`），配对结果容量固定为
   `k(k-1)/2`，没有分配全顶点的 O(n²) 配对数组。
6. **可选有界连通块标签传播。** `BLOCK_LP=1` 且已经有满足最终 `1.10`
   容量约束的最好可行标签时启用。当前版本只在单位点权重下把一个有向分区对
   `(A,B)` 的最多 8 个边界种子扩展为连通块，块大小最多 16。种子按
   `g(v,A→B)` 降序、顶点编号升序选取；没有正收益门槛，因此允许从非正种子
   穿过屏障。每个 CUDA block 负责一个种子的贪心增长，前沿最多 256 个点，
   溢出时保留 `hash(seed,target,vertex)` 最小的点并记录溢出轮数和边访问数。

   对当前块 `S`，候选点的边际收益为
   `Δ(x|S,B)=g(x,A→B)+2*w(x,S)`，允许中间前缀为负；只记录到目前为止的
   最好正收益前缀。等价的块收益为
   `G(S,A→B)=w(S,V_B)-w(S,V_A minus S)`，也就是
   `sum g(v,A→B)+2*w(E(S))`。自环从 `g` 和内部边重数中排除；平行边按重数
   计算。候选总数固定为 `8*k*(k-1)` 的配置上限，不构造无界的全点对数组。

   主机按收益降序、块大小、源区、目标区、种子编号排序，先消除顶点重叠，
   再用保守的目标区容量约束 `sum incoming <= U-W_B` 选取候选；不做一般的
   多区净流量配额。不同候选之间允许存在边，但提交前复制标签快照、统一应用
   选中块并完整重算切边，只有严格正的完整批次收益才接受，因此不会把单块
   收益简单相加。接受后完整重建邻居标签计数、负载和切边；每轮再运行原有
   polish，最多两轮，且无接受交换时提前结束。该流程仍属于
   `SingleGPUPartitioner`，不是串联的第二个程序。
7. **可行解记录与结束。** 计算切边并保存最好可行标签；最后恢复它，
   最多做 20 轮带冲突消解的正收益传播，再输出最好可行结果。
   recorder 是搜索内部的接受/回退机制，不是外接精修程序。

## 实现边界

配对开关及第一轮统一参数为：

```ini
PAIR_EXCHANGE=0
PAIR_EXCHANGE_ROUNDS=2
PAIR_TOP_TARGETS=2
PAIR_BUCKET_LIMIT=32
PAIR_VERIFY=0

BLOCK_LP=0
BLOCK_MAX_SIZE=16
BLOCK_SEEDS_PER_PAIR=8
BLOCK_FRONTIER_LIMIT=256
BLOCK_ROUNDS=2
BLOCK_VERIFY=0

ENABLE_FIELD=1
TIME_BUDGET_SECONDS=0
```

`PAIR_VERIFY=1` 会在提交前用主机 CSR 重新验证每个提出交换的公式，并在提交后检查
标签、负载、冲突和完整双向切边。主程序的 `cut` 仍按双向 CSR 条目计数；因此调试
检查中完整 `cut` 的下降量是接受交换收益之和的两倍，对应的无向切边下降量才等于
公式收益之和。

邻接扫描、扩散、候选生成、标签更新等在 CUDA 中执行；C++ 主机代码负责
流程、部分配额决策、同步与 I/O。因此是 C++/CUDA 单 GPU 算法，不是完全无主机参与。
邻居标签计数缓存、增量切边和高阶点 warp 路径属于执行优化，不是新划分阶段。
场和标签计数包含 O(nk) 状态，不能仅根据 O(n+m) 的 CSR 估计显存。

`BLOCK_VERIFY=1` 会在提交前用独立的主机 CSR 检查每个正收益候选的标签、连通性、
块收益公式和最终试标签，并检查完整批次切边；检查失败直接抛出错误，不输出看似正常
的结果。默认关闭的新阶段不分配其 CUDA 缓冲区，也不改变原有 LP 的流程。

`TIME_BUDGET_SECONDS>0` 是实验用时间截止：只在完整全局周期边界检查，超时周期恢复
到周期开始的标签、最好可行解和缓存状态，然后执行统一最终 polish，并输出实际预算偏差。
时间预算启用时使用独立的 device checkpoint 缓存，不复用 descent 的旧标签缓存。

Python 多起点择优、CPU FM/小组交换、CPU 区域最小割、递归二分、PyTorch
软标签均不是该主算法。不能将这些实验的最好切边和默认 CUDA 单次时间拼接报告。
完整质量对照须固定入口、配置、起点数，覆盖 k=2/4/8/16/32；报告真实切边、
最大负载及全部搜索耗时。当前计时范围也不包含完整的读图、构造分配和写盘成本。

## 当前局限与后续主线

当前仍是由多个启发式组成的基线，不能因为统一了入口就称为质量突破：
场投影优化结构偏好，descent 优化切边，balance 优化负载压力，三者可能相互抵消。
单点正收益搜索难以跨越需要联合迁移的屏障；配对交换现在提供了一个有界的两点
验证机制，但它只处理单位点权重下的两区互换，不是一般的容量协同联合迁移，也不
保证质量质变。默认 `PAIR_EXCHANGE=0`，关闭时不进入该流程。

截至 2026-09-08，有界连通块第一版已经实现并通过
[`test_block_lp.py`](test_block_lp.py)；测试覆盖连通增长、非正种子、最佳正前缀、
精确批次切边、容量淘汰、自环、随机 CSR 和关闭开关回归。它仍是验证性可选机制：
候选增长与前沿扫描的成本随边访问量增加，容量筛选采用保守的 incoming-only 规则，
并没有求解一般联合迁移的最优批次。

本版本固定 `products`、`com-LiveJournal`，`k=4,8,32`、seed=0 做了机会诊断和
A/B/C 对照，详见 [`BLOCK_LP_DIAGNOSTICS_20260908.md`](BLOCK_LP_DIAGNOSTICS_20260908.md)。
六组都产生并接受了正收益块，但固定 20 个全局周期的原始 LP 延长搜索 C 在六组
都优于当前两轮 block B；因此没有追加 seed=1,2,3 复验，也没有把 block LP 提升为
主线默认算法。当前唯一合理的后续方向是先降低候选增长成本或改进容量/调度策略；
不在本轮继续扫描桶大小、轮数或扩展更大联合块。

结构场开关的六组 A/B/C 诊断见
[`FIELD_TOGGLE_DIAGNOSTICS_20260908.md`](FIELD_TOGGLE_DIAGNOSTICS_20260908.md)，
完整周期轨迹见 [`FIELD_CYCLE_TRAJECTORIES_20260908.md`](FIELD_CYCLE_TRAJECTORIES_20260908.md)。
结果显示关闭场在固定 5 周期下通常更差，但用相同时间继续运行无场 LP 的 C 在 5/6
案例优于 A；因此保留场的默认开启行为和显式开关，不新增自适应规则。

截至 2026-09-08，上述两点交换第一版已经完成并通过小图验证；测试覆盖满载、相邻修正、
修正后拒绝、共享端点、跨交换邻接、孤立点、平行边、多分区候选和随机 CSR。六组
`products/com-LiveJournal × k=4/8/32` 的 seed=0 诊断和 A/B/C 等时间对照见
[`PAIR_EXCHANGE_DIAGNOSTICS_20260908.md`](PAIR_EXCHANGE_DIAGNOSTICS_20260908.md)。
结果显示配对机会存在，但 k=8/32 的冲突淘汰很重，额外时间主要在配对筛选和随后
descent，不是邻居标签缓存重建；B 在六组中都没有胜过同等时间延长的原始 LP C。
因此两点交换保留为默认关闭的可选实验，不宣称质量突破，也不把它与 CPU 后处理结果
合并报告。唯一排定的后续实验是固定候选生成参数的 GPU 冲突调度消融；若仍不胜 C，
停止继续扩展两点交换，再考虑有界连通小组联合迁移。

## 2026-09-09：GPU-LP 粗化与 Jet 后半段隔离实验

`multilevel_lp` 是独立研究 executable，不改变默认单层主程序。它的 `lp` 模式只
输出 GPU-LP 聚类得到的完整加权层次；`app/jet_gpu_lp_import` 再用 Jet 原生的
METIS 最粗层初始化、投影和 refinement。这样可以直接比较“Jet 原粗化”和“自研
GPU-LP 粗化”，而不把自研初始化或最终 polish 混入 B。每层会检查 map、重量守恒、
双向加权 CSR、去自环和随机标签投影切边守恒；`GPU_LP_STRICT_VERIFY=1` 提供逐边
严格检查。

该实验的 Jet 接口、seed、层次文件格式、六组 seed=0 结果及当前停止阈值差异，见
[`GPU_LP_JET_COARSEN_EXPERIMENT_20260909.md`](GPU_LP_JET_COARSEN_EXPERIMENT_20260909.md)。
这六组已经证明接口替换正确，但还不能视为同等粗化规模的聚类质量结论。

同一 executable 还提供可选的 BASC（Bounded Anchor-Support Coarsening）研究后端：
确定性局部 anchor、K=1/2/4 候选、常数状态 support、4 桶置信度 admission、一次
leftover expansion 和 singleton fallback。第一版固定 K=2，容量采用 64-bit CAS，
粗 CSR 暂用 host sort/reduce；默认 `coarsen_method=lp` 不改变已有研究路径。BASC
小图和 kim2 smoke 已通过，products/k=4 的首轮结果有质量信号但尚未超过 Jet 原版，
因此保持可选，不称为质量突破。实现和可复核命令见上述报告及
[`experiments/test_basc_small.py`](experiments/test_basc_small.py)。

随后固定 `STOP_RATIO=0.85`、`MAX_LEVELS=24`、`seed=0` 完成 products 与
LiveJournal 的 k=4/8/32、BASC K=1/2/4 消融。18 个 BASC 输出和 6 个 Jet A
输出均通过独立 CSR/容量校验；K=2 只在 products/k=4 相对同批 A 小幅改善，
没有跨图跨 k 的稳定提升，故不改变默认主线。完整表格和粗化耗时见
[`GPU_LP_JET_COARSEN_EXPERIMENT_20260909.md`](GPU_LP_JET_COARSEN_EXPERIMENT_20260909.md)。

2026-09-09 的固定无场 baseline 诊断见
[`QUALITY_OPTIMIZATION_DIAGNOSTICS_20260909.md`](QUALITY_OPTIMIZATION_DIAGNOSTICS_20260909.md)。
该轮只增加了每批候选、容量淘汰、单点评分与完整批次切边变化的有限日志；全部相邻冲突过滤、
真实变差批次回滚和最小超载修复均未在六组 `products/com-LiveJournal × k=4,8,32` 中形成稳定改善，
因此没有进入主线，也没有继续堆叠后处理。

2026-09-09 进一步验证了一个单独的 descent 微批次调度：`DESCENT_MICRO_BATCH=256` 时，
每个目标区小批提交后立即重建/更新邻居标签计数，再重新生成下一批候选；每轮最多 8 个微批次。
它不改变 field、balance、初始化、polish 或容量规则，默认仍为 `DESCENT_MICRO_BATCH=0`。
在两图五个 k、seed=0,1,2 的完整对照中，products 五个 k 的平均切边均下降，
LiveJournal 的 k=8,16,32 稳定下降，但 k=2,4 分别平均上升 4.23%、2.94%；完整结果见
[`QUALITY_OPTIMIZATION_MICRO_BATCH_20260909.md`](QUALITY_OPTIMIZATION_MICRO_BATCH_20260909.md)。
因此该调度保留为质量优先的可选候选，不宣称为无条件主线改进；代价是完整搜索时间约增加
2.6–8.9 倍。`test_descent_micro.py` 和 `INCREMENTAL_CUT_VERIFY=1` 已验证多次提交后的
标签、容量、缓存和完整 CSR 切边一致。
