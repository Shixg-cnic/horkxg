# 结构场开关诊断与时间对照（2026-09-08）

## 配置与规则

测试范围为 `products`、`com-LiveJournal`，`k=4,8,32`，固定
`SEARCH_SEED=0`、`MAX_VERTEX_RATIO=1.10`。三种版本均保持
`PAIR_EXCHANGE=0`、`BLOCK_LP=0`、其他搜索参数不变：

| 版本 | 配置 |
| --- | --- |
| A | `ENABLE_FIELD=1`, `GLOBAL_CYCLES=5` |
| B | `ENABLE_FIELD=0`, `GLOBAL_CYCLES=5` |
| C | `ENABLE_FIELD=0`, `GLOBAL_CYCLES=50` 上限，`TIME_BUDGET_SECONDS` 取同案例 A 的实测总时间 |

C 在每个完整周期结束后检查预算；超时周期恢复到周期开始状态，随后执行统一的最终
polish。表中的 `budget deviation` 是最终 `partition_seconds - TIME_BUDGET_SECONDS`，
因此包含最后一个完整周期的超时部分和 polish。没有按切边结果选择 C 的周期数。

## 结论与决策

- 代码开关默认开启，`ENABLE_FIELD=0` 跳过所有场构建、扩散和 field projection；
  `FIELD_ROUNDS=0` 仍是另一种配置，不再被用作关闭开关。
- 关闭路径保持初始化、容量放宽/收紧、balance、descent、recorder 和 polish；
  小图测试确认场缓存未被访问。
- A/B/C 的答案是：结构场有一定引导作用，但收益依赖图和 k，且承担可见计算成本。
  当前不移除结构场，也不新增自适应规则；保留 `ENABLE_FIELD` 作为显式实验开关。
- 共享 GPU 会影响绝对墙钟时间；本轮所有版本顺序执行，C 的实际预算偏差已单独记录。
